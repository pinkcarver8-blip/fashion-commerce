### A1. 검증 가능한 바이브 코딩 드롭형 패션 커머스 (커머스 정합성 + AI 하네스)

- **논리:** 근거와 결론이 대체로 맞습니다. 자기 비판(근거가 경력 공고 위주, 하네스가 평가된다는 직접 증거 없음)도 정확합니다.
  - 약점 1: "락 전략 6종 비교 실험"을 차별화 장치로 내세웁니다. 그런데 이 비교는 항해 플러스의 주차 과제 자체이고 인프런 강좌의 목차와도 같아, **비교 실험 자체는 차별화가 되지 못합니다**(5절).
  - 약점 2: 스택에서 Boot 4.0.x를 권고했는데, 4.0의 OSS 지원은 2026-12-31에 끝납니다(V19).
- **충분성:** PG 제약(가상계좌 계약 필요)을 정확히 반영한 유일한 보고서입니다. 하지만 코딩테스트 관문(무신사 1,700명 → 400명)을 "덧붙임"으로만 처리했습니다.
- **판정: 조건부 수용.** 조건은 ① 락 비교를 핵심 차별화가 아닌 "기본기 증빙"으로 격하 ② Boot 4.1.x로 수정 ③ 코딩테스트·AI 과제 대비 트랙을 본 계획에 편입하는 것입니다.

- **판정: 조건부 수용.** 단독 1순위로는 부족하고, **1순위 프로젝트의 2단계(입점 브랜드 확장)**로 두는 것이 근거에 맞습니다.

### C1. 정시 드롭 패션 커머스: 재고와 돈의 정합성을 수치로 증명
- **신빙성:** 높음. 한경 일화(V2)는 사용자 프로필과 가장 직접 맞닿는 근거입니다(부트캠프 + 바이브코딩 → 예외 처리·대용량 설계 질문에서 탈락). 단 표본은 1건입니다.
- **논리:** 맞습니다. "드롭 1회 리플레이" 시연 구성이 세 보고서 중 가장 구체적입니다.
  - 오류: 핵심 기능에 가상계좌를 넣었는데, C가 인용한 D01(같은 문서)에 "문서용 테스트 키로 가상계좌 테스트 불가"가 적혀 있습니다(V14).
  - 근거 약화: 9월 의복 -4.8%는 확인하지 못했습니다(V10).
  - 근거 노후: 정산 규제 근거로 2024-10 기사(D14)를 썼는데, 2026-09 개정안이 더 최신입니다.
- **충분성:** "AI 없이 설명하는 능력"(공통 기반 2)을 다룬 유일한 보고서입니다. 국내 AI 금지 전형(네이버·카카오 등, V16) 대비로 중요합니다.
- **판정: 조건부 수용.** 가상계좌는 "구조만 설계하고 테스트 불가는 문서로 명시" 또는 "모의 PG로 시나리오 재현"으로 바꿔야 합니다. 락 비교의 격하 조건은 A1과 같습니다.

### C2. 입점형 오픈마켓 (셀러, 정산, 운영 백오피스)
- **신빙성:** 중상. 에이블리 인턴(V21)이 주니어 근거를 제공합니다. 오늘의집 정산 조직 근거(N20, N28)는 요약만 확인했습니다.
- **논리:** 맞습니다. "1순위부터 시작하되 M0에서 하위 주문 구조만이라도 미리 정해 두라"는 권고는 세 보고서 중 가장 실용적인 통합 설계 조언입니다.
- **판정: 조건부 수용**(A2와 같이 1순위의 2단계로 병합).

### C3. 권역 재고·배송 슬롯 장보기
- **신빙성:** 근거가 컬리 한 곳에 편중되어 있습니다(C도 인정).
- **논리:** "슬롯 = 시간 재고"라는 아이디어는 신선하고, 흔한 선착순 주제와 다르다는 점에서 의미가 있습니다. 그러나 사용자의 요구(송장 발행, 대형 이커머스 구조)와 거리가 있습니다.
- **판정: 기각(주 제안).** 아이디어 일부(시간 자원 예약)는 1순위의 드롭 예약 시간대나 배송일 지정으로 흡수할 수 있습니다.

### B1. (자기) 검증된 바이브 코딩: 패션 버티컬 + 주간 한정 드롭
- **자기 오류:**

  - ② 가상계좌를 P0(#28)에 넣고 테스트 제약을 놓쳤습니다(V14).

- **판정: 조건부 수용**(A1·C1과 병합).

### B2. (자기) 입점형 오픈마켓 + 정산·대사

- **평가:** 뷰티 컨셉 근거는 올리브영 기술 블로그에 치우쳐 있습니다. AI 기능의 신입 직결 근거는 A3와 같은 수준으로 약합니다.

- **판정: 기각(주 제안) / 확장 모듈로 수용.**

## 5. 공통 맹점과 같은 모델 편향 점검

### 5-1. 세 보고서가 거의 같은 결론을 냈다
1순위(패션 드롭 + 재고·결제 정합성 + AI 검증 프로세스), 2순위(리빙 오픈마켓 + 정산), 스택(React·Vite·TS / Spring Boot 4 / MySQL 8.4 / Redis / Docker / Testcontainers / k6), 비용, 클라우드 전환 기준까지 사실상 같습니다. 독립 조사였는데도 이렇게 일치한 이유를 두 가지로 나눠 봤습니다.

**근거가 강해서 일치한 부분 (편향 아님)**
- 커머스 도메인은 사용자가 정한 전제입니다.
- React + Spring Boot + MySQL 타당성은 세 보고서가 각각 다른 플랫폼·공고로 확인했습니다(사람인, 잡코리아, 위시켓, 무신사·컬리 공고 원문).
- "AI 도구 활용 + 결과 검증"을 평가한다는 근거는 서로 다른 기업 전형(무신사, 컬리, CJ, LG CNS, 넥슨, HD현대)에서 독립적으로 나옵니다. 여러 보고서가 각자 직접 확인했습니다(V1, V6, V15).
- PG 연동 사실(10분 승인, 멱등키 15일, 웹훅 재전송)은 공식 문서라 누가 봐도 같습니다.

**흔한 정답 패턴일 가능성이 높은 부분 (편향 의심)**
1. **"선착순·드롭 동시성 + 락 비교 실험"이 차별화라는 판단.** 세 보고서 모두 "주제는 흔하지만 비교 실험과 측정으로 차별화한다"고 썼습니다. 그런데 재확인 결과는 다음과 같습니다.
   - 항해 플러스 백엔드 과정은 **비관적·낙관적·분산 락 적용과 비교를 주차 과제로 요구**합니다(수강 후기 다수, 공식 커리큘럼은 미확인).
   - 인프런 동시성 강좌(수강생 3,654명)의 목차가 곧 A·C가 제안한 6종 비교의 대부분입니다.
   - GitHub에 "선착순 동시성" 저장소가 45개 이상 있습니다(설명에 그 단어를 쓴 것만 센 값이므로 실제는 더 많을 것으로 추정).
   - 루프팩 BE 과정은 커머스 + PG 장애 격리(Resilience4j)를 다룹니다.
   - → **"락 6종 비교 + k6 수치"는 2026년 부트캠프 수료자의 표준 산출물에 가깝습니다.** 차별화 근거로 삼은 것은 세 보고서의 공통 과대평가입니다.
2. **반대 증거:** "흔해도 깊이 있게 하면 평가받는다"는 면접 후기(꼬리 질문으로 깊이를 확인)는 있습니다. 동시성은 기본 CS 질문이기도 합니다. 즉 **해야 할 기본기이지 플러스 알파는 아닙니다.** "흔해서 차별화가 안 된다"는 직접 증거(면접관 발언)도, "깊이로 차별화된다"는 직접 증거도 찾지 못했습니다. 양쪽 모두 정황입니다.
3. **"무신사가 근거가 가장 많다 → 패션"의 순환.** 무신사가 근거가 가장 많은 이유는 기사 노출(AI 네이티브 신입 채용 보도)이 많아 검색에 잘 걸리기 때문일 수 있습니다. 패션이 채용에 유리하다는 독립 근거는 아닙니다. 실제로 F&F 신입 공고(V22)는 커머스가 아니라 ERP/AI 사내 시스템 직무였습니다.

### 5-2. 그렇다면 상대적으로 덜 흔한 것은 무엇인가 (세 보고서의 자료에서 재구성)
- **외부 시스템이 끼어든 종단 정합성:**
  - 결제 승인 타임아웃, 웹훅 재전송(토스 최대 7회, 약 3일 19시간)·순서 역전(포트원 명시), 보상 취소, 일일 대사
  - 부트캠프 과제가 PG 장애 격리까지는 다루지만, 대사(reconciliation)와 웹훅 재전송 재현까지 다룬 정황은 이번 조사에서 보지 못했습니다(판단, 근거 약함).
- **AI로 만든 결과물의 서비스화 하네스:** 오늘의집 올리고(V8)의 4대 허들(인프라·인증·DB 스키마·보안)과 사람 승인 지점을 개인 프로젝트 규모로 재현하는 것입니다. 국내 대형사의 실제 운영 사례가 있고, 채용 전형(무신사·컬리·넥슨)의 "AI 활용 과정 평가"와 직접 이어집니다. 2026년 하반기에 생긴 흐름이라 부트캠프 표준 산출물이 되기 전입니다(판단).
- **셀러·백오피스·정산:** 에이블리 인턴 공고(V21)가 주니어 업무로 명시하고, 학습 콘텐츠가 적습니다(C의 판단, 정량 근거 없음).

### 5-3. 세 보고서가 공통으로 놓친 것
1. **가장 큰 관문은 포트폴리오가 아니라 코딩테스트일 수 있습니다.**
   - 무신사 AI 네이티브 트랙은 1,700여 명 → 400명으로 **1차 코딩테스트에서 약 76%가 탈락**했고, 그 뒤에 AI 도구 테스트가 있었습니다(V1).
   - 네이버·카카오는 AI를 금지하고, 넥슨은 코딩테스트를 폐지하고 AI 활용 평가로 대체했습니다. 전형이 갈라져 있습니다.
   - 세 보고서는 모두 이를 "병행하라"는 덧붙임으로만 처리했습니다. **최종 기획에는 "알고리즘 코딩테스트"와 "시간 제한 AI 활용 과제" 연습을 프로젝트와 같은 무게의 트랙으로 넣어야 합니다.**
2. **신입 공고 원문 표본이 사실상 없습니다.** 세 보고서의 핵심 공고는 대부분 경력 5년 이상입니다. 주니어 공고는 에이블리 인턴(셀러·백오피스, 라이브 코딩, AI 언급 없음)과 무신사 트랙, F&F(사내 시스템) 정도입니다. **"신입에게 무엇을 보는가"를 신입·인턴 공고 20~30건으로 직접 확인하는 작업**이 여전히 남아 있습니다(A가 지적했지만 아무도 수행하지 않음).
3. **프론트엔드 플러스 알파가 비어 있습니다.**
   - 사용자의 기본 직무는 풀스택인데, 세 제안 모두 백엔드 중심입니다.
   - 무신사 전시개발팀은 Home·추천·메뉴·PLP·SRP를 맡고(V17 공고 본문), 컬리 FE 우대는 정량적 성능 최적화·웹 접근성·반응형입니다(B S32).
   - 모바일 비중은 76.4%입니다(V10).
   - 모바일 웹 성능(Core Web Vitals 측정), 접근성, PLP·검색 UX(Baymard)를 수치로 개선하는 FE 축이 없습니다.
4. **채용 시즌 타이밍을 아무도 다루지 않았습니다.** 확인된 신입 트랙 공고 시점은 무신사 1월(2026), 에이블리 인턴 1월, 넥슨 8월, LG CNS·CJ 9월입니다. "기간 무제한"이라도 첫 지원 시점에 맞춘 "여기서 멈춰도 포트폴리오가 성립하는 지점"(A가 언급)을 날짜와 연결해야 합니다. 무신사가 2027년 1월에도 같은 트랙을 열지는 **미확인**입니다.
5. **결제수단 테스트 범위:** 가상계좌는 계약 없이 테스트할 수 없습니다(V14). B와 C는 이를 놓쳤고 A만 반영했습니다. 포트원 V2의 테스트 채널에서 가상계좌가 되는지는 **미확인**입니다.
6. **상품 데이터 생성:** 검색·필터 실험에는 수천 SKU가 필요합니다. 저작권 없는 생성 방법과 데이터 생성 자체를 AI 하네스로 다루는 방법은 A만 질문으로 남겼습니다.

## 6. 최종 입장

### 6-1. 최종 제안 1~3순위

**1순위: "AI 검증 하네스로 만든 운영 등급 패션 커머스 — 외부 연동까지 포함한 주문·결제·환불·대사 정합성"**
- **핵심 내용:** 가상 패션 편집숍(직매입, 상시 판매 + 주간 드롭)을 만듭니다.
- **중심축:** 드롭 동시성이 아니라 **"돈과 재고가 외부 시스템(PG·택배)까지 포함해 한 건도 어긋나지 않음을 재현 테스트와 대사로 증명"**하는 것입니다.
  - 결제 승인 타임아웃
  - 웹훅 중복·역순·지연 재현(토스 재전송 정책을 테스트로 모사)
  - 보상 취소, 부분 취소 금액·쿠폰 안분
  - 반품·환급 기한(전자상거래법)
  - 일일 대사 리포트
- **재고 동시성의 위치:** 기본기 증빙으로 두고 압축합니다. 조건부 UPDATE, 비관적 락, Shopify식 행 풀 + SKIP LOCKED 정도만 비교하고, 비교 자체를 차별화로 내세우지 않습니다.
- **플러스 알파:** 개발 전 과정을 **AI 하네스**로 운영하고 공개합니다(오늘의집 올리고의 4대 허들을 개인 규모로 재현).
  - 규칙·컨텍스트 문서
  - 불변식 테스트, 아키텍처 테스트, SAST·비밀값 스캔 CI
  - "AI 제안 / 내 판단 / 검증" PR 기록
  - AI가 틀린 사례집
- **병행 트랙:** 알고리즘 코딩테스트와 시간 제한 AI 활용 과제를 프로젝트와 같은 비중으로 준비합니다.
- **기반:** A1 + B1 + C1 병합. C1의 시연 구성과 "AI 없이 설명", A1의 가상계좌 제약 반영과 하네스 근거, B1의 대사·정산 규칙 근거를 가져옵니다. 세 보고서의 "락 비교 = 차별화" 주장은 격하했습니다.
- **순위 이유:** 근거가 가장 두껍고(국내 전형·공고·공식 문서), 편향 점검(5절) 뒤에도 남는 차별화 요소(종단 정합성, 하네스)를 중심에 둔 안입니다. 클라우드 없이 로컬에서 핵심 가치를 대부분 만들 수 있습니다.

**2순위: "패션 편집숍의 입점 브랜드 확장 — 셀러 백오피스·정산·구매확정·대사 (오픈마켓 모델)"**
- **핵심 내용:** 1순위의 주문 모델을 처음부터 "주문 → 판매자주문 → 주문상품" 3단으로 설계해 두고, 2단계에서 입점 브랜드(위탁)를 추가합니다.
- **범위:**
  - 셀러 어드민(상품·재고·송장·정산 조회)
  - 판매자별 배송비·묶음배송
  - 플랫폼·셀러 부담 쿠폰 안분
  - 자동 구매확정 배치
  - 정산 배치(재실행 안전, Spring Batch)
  - PG 대사
- **규칙 근거:** 지어내지 않고 2026-09 정무위 통과 대규모유통업법 개정안(직매입 35일, 위수탁 20일, 확정 여부는 미정)과 토스 부분취소·과세 규칙에 둡니다.
- **단독 프로젝트로 할 경우:** 컨셉은 리빙 오픈마켓입니다.
- **기반:** A2 + B2 + C2 병합. 1순위와의 결합 방식은 C2의 M0 하위 주문 권고를 따릅니다.
- **순위 이유:** 주니어 수준 근거(에이블리 셀러 플랫폼·백오피스)와 차별성은 있습니다. 하지만 시연 효과가 약하고 범위가 커서, 1순위의 2단계로 두는 것이 근거에 맞습니다.

**3순위: "AI 기능 확장 모듈 — 평가셋으로 측정하는 하이브리드 검색·리뷰 요약 (끄면 폴백)"**
- **핵심 내용:** 1순위 위에 OpenSearch(nori + 벡터) 하이브리드 검색과 리뷰 요약을 붙입니다.
  - 질의-정답 평가셋으로 검색 품질 전후를 측정합니다.
  - LLM 비용·지연·실패 폴백과 프롬프트 인젝션(리뷰 본문 경유) 방어를 갖춥니다.
  - 모든 AI 기능에 끄는 스위치를 둡니다.
  - FE 플러스 알파(모바일 웹 성능·접근성·PLP UX 수치 개선)를 이 단계에서 함께 다뤄, 풀스택 축의 공백을 메웁니다.
- **기반:** A3 + B3 병합(C의 "선택 모듈" 판단 수용). FE 축은 공통 맹점(5-3-3)에서 새로 추가했습니다.
- **순위 이유:** 트렌드 근거는 강하지만 신입 직결 근거가 약하고 비용이 듭니다. C3(퀵커머스)는 근거 편중으로 제외했습니다.
