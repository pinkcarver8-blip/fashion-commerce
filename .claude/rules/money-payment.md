# [엄격] 결제·금액·환불

원문: 작업진행.md A5-1, A5-5, A5-6, 계약은 B5·B6. 작업 전에 이 원문과 이슈의 시나리오를 먼저 읽는다.

- 금액은 모두 서버가 계산한다. 클라이언트가 보낸 금액을 믿지 않는다.
- 승인·취소 재시도는 시도 ID나 취소 요청 ID로 정해진 **같은 멱등키**를 쓴다(`confirm-{attemptId}`, `cancel-{pg_cancel uid}`. 결제 한 건에 취소 기록은 하나, ADR-006b). 재시도에 새 멱등키를 만들지 않는다(E51).
- paymentKey는 `CONFIRMING` 전이와 같은 트랜잭션에 저장한다.
- 새 결제 시도는 주문이 `PAYMENT_PENDING`일 때만 만든다.
- 취소는 취소 요청 상태를 먼저 기록한 뒤 PG를 호출한다.
- orderId 조회에 의존하는 복구를 만들지 않는다(위젯 키로 호출할 수 없다).
- PG 스텁 응답은 R0에서 실제로 받은 응답으로만 만든다. 테스트와 CI는 토스 테스트 서버에 의존하지 않는다.
- 환급 기한(3영업일)과 영업일 계산은 단위 테스트로 고정한다.
- 금액·상태를 바꾸는 코드는 테스트 없이 머지하지 않는다. 테스트는 같은 PR에서 통과시킨다.
