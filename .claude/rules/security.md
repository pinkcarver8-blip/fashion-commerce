# [엄격] 보안: 인증·인가·관리자·개인정보

**번거롭더라도 보안을 우선한다**(CLAUDE.md 절대 규칙 1). 편의를 위해 보안을 양보하는 구현은 기본안이 될 수 없다.

원문: 작업진행.md A5-9(S1~S12), A5-10, ADR-008. 작업 전에 원문의 해당 S 번호를 먼저 읽는다.

- 기본 거부: 공개 API만 명시적으로 열고 나머지는 닫는다. 관리자 컨트롤러는 `admin` 패키지와 `/api/admin/**`에만 둔다.
- 주문·결제·배송 API는 소유자 검사 없이 머지하지 않는다(S12, E46).
- 요청 DTO에 권한 필드를 두지 않는다. 엔티티에 요청을 직접 바인딩하지 않는다. 관리자 계정은 API로 만들지 않는다(S2).
- 관리자 계정·토큰은 고객과 분리한다(별도 테이블·로그인, 용도 표시, 서명 키 분리)(S3).
- 액세스 토큰은 메모리에만 두고 Authorization 헤더로 보낸다. 리프레시 토큰은 HttpOnly·Secure 쿠키. CORS 와일드카드 금지(S4).
- 고객 입력을 원시 HTML로 렌더링하지 않는다(S5).
- 비밀번호는 솔트 해시, 민감정보 암호화, 로그·관리자 응답은 마스킹한다. 기본 비밀번호를 코드·시드에 두지 않는다(S6, S8).
