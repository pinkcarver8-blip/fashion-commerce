# 테스트 작성 규칙

원문: 작업진행.md A4, A5-7.

- **테스트가 실패하면 테스트가 아니라 코드를 고친다.** [엄격] 영역의 기존 테스트를 고쳐야 하면 PR에 이유를 적고 사용자 승인을 받는다.
- 공개 인터페이스(모듈 API, HTTP 경계)와 결과(불변식) 기준으로 쓴다. 내부 구현에 붙이지 않는다. 스냅샷 테스트는 쓰지 않는다.
- RTL은 역할과 문구로 요소를 찾는다.
- 테스트 이름에 작업 ID와 E-ID를 넣는다.
- 단위 테스트는 로직·분기가 있는 곳만 쓴다.
- 통합 테스트는 Testcontainers(MySQL·Redis)와 PG 스텁을 쓴다. 토스 테스트 서버를 부르지 않는다.
