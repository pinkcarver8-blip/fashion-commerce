# [엄격] 공유 모듈

원문: ADR-001 보충 "공유 모듈", 작업진행.md A3-8.

- 두 모듈이 같이 쓰는 **업무 규칙**(배송비, 할인, 재고 판단 등)은 공유 모듈로 옮기지 않는다. 그 규칙의 주인 모듈이 `<모듈>.api`로 연다.
- 공유 모듈에는 값(record·enum·인터페이스·표시)과 앱 설정(`platform`)만 둔다. DB 도구, `@Service`·`@Repository`·`@Transactional`은 쓰지 않는다.
- `money`·`id`·`error`·`identity`의 정적 함수는 자기 타입을 만드는 것만 둔다. 아무 모듈도 `platform`을 부르지 않는다.
- 클래스나 공개 멤버를 더하거나 지우려면 `shared-modules-allowlist.txt`를 고쳐야 하고, 이 목록 변경은 **단위를 시작할 때 사용자 승인**을 받는다. 단위 중간에 필요해지면 멈추고 묻는다.

## 공유 보안 설정의 약점과 막는 장치 (2026-11-28 사용자 지시: 다음 작업에서도 이어서 한다)

**약점**: `platform`의 보안 설정(필터 체인, 토큰 검사)과 `identity`의 주체 클래스는 모든 모듈이 같이 쓴다. 여기 실수 하나가 모든 모듈에 한꺼번에 퍼진다. 이 경로를 고치는 PR은 아래를 모두 지킨다. 하나라도 빠지면 머지하지 않는다. "작은 정리 작업" 예외(작업진행.md A3-8)를 쓰지 않는다.

1. **주체에는 ID와 용도만 둔다.** 고객 주체는 회원의 외부 ID 하나다. 이메일·이름·비밀번호 해시·권한 목록을 더하지 않는다(더하려면 허용 목록 변경이라 단위 시작 때 묻는다).
2. **주체는 검사를 통과한 토큰에서만 만든다.** 만드는 곳은 `platform`의 토큰 변환기 하나다(ArchUnit `onlyPlatformCreatesPrincipals`). 업무 모듈은 요청 본문·쿼리·헤더로 회원 ID를 받지 않고 주체에서만 얻는다(S2, S12).
3. **토큰 거절 시험을 지우거나 약하게 고치지 않는다**(R1-01 T2: 만료·변조·다른 키·다른 용도·서명 없음 → 401, `StoreTokenRejectionTest`). 필터 체인을 더하면(R1-02 관리자) 같은 시험을 그 체인에도 만든다.
4. **기본 거부, 공개 경로는 `platform` 설정의 목록 한 곳에서만 연다.** 목록에 줄을 더하는 PR은 이유를 PR에 적는다. 다른 모듈은 보안 설정(필터 체인, `HttpSecurity`)을 만들지 않는다(ArchUnit `onlyPlatformConfiguresSecurity`).
5. **엔드포인트 자동 점검**(R1-03에서 만든다): 앱에 등록된 모든 경로를 읽어 공개 목록 밖은 비로그인 401인지 본다. 만든 뒤에는 지우거나 약하게 고치지 않는다.
6. **사람 확인**: 이 경로를 고치는 단위는 독립 검토 요청에 이 6항목을 넣고, [엄격]으로 사용자가 코드를 읽은 뒤 머지한다.
