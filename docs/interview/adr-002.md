# ADR-002 꼬리 질문: Java 버전

[ADR-002](../adr/002-java-version.md)에 대한 예상 질문과 답이다(기획서 §12-3).

## 1. 최신 LTS가 25인데 왜 21을 썼나요?
25를 써서 얻는 것과 확인해야 할 것을 비교했습니다. 25만의 큰 이점은 `synchronized` 안에서 막혀도 가상 스레드가 플랫폼 스레드를 붙잡지 않는 것(JEP 491, JDK 24부터)인데, 이 프로젝트는 가상 스레드를 쓰지 않습니다. 반면 21은 R0에서 Boot 4.1, Hibernate 7.4, QueryDSL 포크 조합으로 빌드와 조회를 이미 확인했습니다. 그래서 21로 시작하고, 가상 스레드를 쓰기로 하면 25를 다시 검토한다고 ADR에 조건을 적었습니다.

## 2. Spring Boot 4.1은 25를 지원하지 않나요?
지원합니다. 공식 문서에 Java 17 이상, 27까지 호환된다고 적혀 있습니다. 그래서 Boot는 결정 이유가 아니었고, 우리가 직접 확인한 조합(R0-04)과 가상 스레드 사용 여부가 이유였습니다.

## 3. 나중에 25로 올린다면 무엇을 하나요?
Gradle toolchain의 `languageVersion`과 CI의 JDK를 25로 바꾸고, 전체 테스트를 다시 돌립니다. QueryDSL처럼 주석 처리기나 바이트코드를 다루는 도구(QueryDSL APT, ArchUnit, JaCoCo)는 새 클래스 파일 버전을 지원하는 판인지 먼저 확인합니다. 결정은 새 ADR로 남기고 ADR-002는 "대체됨"으로 바꿉니다.

## 4. 버전을 어떻게 강제하나요?
Gradle toolchain을 21로 고정해서, 개발자 PC에 다른 JDK가 있어도 21로 컴파일합니다. CI도 `setup-java`로 21을 고정합니다. 문서로만 정하지 않고 빌드 설정으로 막습니다.

## 5. 가상 스레드는 왜 안 썼나요?
계획 단계에서 필요한 이유가 없었습니다. 드롭처럼 재고 행 하나에 요청이 몰리는 경우에는 스레드 수보다 DB 잠금이 먼저 병목이 될 것으로 봅니다. 다만 이것은 예상이라 부하 테스트로 확인합니다. 측정에서 스레드 풀이 병목으로 나오면 그때 가상 스레드와 25를 함께 검토합니다.
