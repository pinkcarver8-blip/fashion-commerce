# AI 산출물 검증 점검표

작업진행.md A3-9의 본문이다. AI가 만든 문서·코드를 내보내기 전에 이 표로 확인한다. 실수가 나오면 그 실수를 잡는 항목을 이 표나 `tools/doc-check`에 더하고, 아래 실수 이력에 남긴다(4층).

## 1층: 쓰는 순간

**절대 규칙 확인**(CLAUDE.md 맨 앞)
- [ ] 보안을 조금이라도 양보한 안이 기본 추천이 되지 않았다. 양보한 안을 보여 줄 때는 맨 앞에 "보안을 양보함: 무엇을, 얼마나"를 썼다.
- [ ] 사용자에게 가는 글의 본문에 설정·코드 이름이 없다(실제 이름은 끝의 "참고: 실제 이름" 칸에만). 풀이 없는 전문 용어·영어 약어가 없다. 무엇을 막으려고 검토하는지 장면으로 썼다. 판단마다 실제 장면 예시가 있다. 추천에는 의문점·약점·미확인·질문이 붙어 있다.
- [ ] 결정을 묻는 글은 항목마다 "추천 / 추천의 문제 / 다른 선택과 그 문제"가 있다. 묻기 전에 추천을 한 번 더 검토했고(보안 양보 여부, 내가 틀리면 누가 언제 아는가), 바뀐 추천은 표시했다. 한꺼번에 승인하게 유도하는 문장이 없다.

**사실과 숫자**

- [ ] 사실 문장마다 근거가 있다(파일·절, 공식 문서와 확인 날짜, R0 실측). 없으면 쓰지 않거나 "(미확인)"을 붙였다.
- [ ] 숫자마다 계산식이나 출처가 있다. 시간 값은 "언제부터 세나"(기준 시각)를 함께 적었다.
- [ ] 실측·문서가 확인한 범위를 넘겨 일반화하지 않았다(예: "인증 없이 닫은 결제창을 다시 열 수 있다"를 "언제든 다시 열 수 있다"로 쓰지 않는다).
- [ ] 라이브러리·도구의 동작(어노테이션이 남는지, 기본값 등)은 공식 문서나 소스로 확인했다.
- [ ] "막는다·보장한다·강제한다"는 도구가 실제로 잡는 범위만 썼고, 못 잡는 것도 적었다.
- [ ] 모듈이 주어인 문장("A가 B를 부른다·바꾼다·읽는다")을 ADR-001 동기 호출 표와 대조했다.

## 2층: 머지 전 (작업 하나마다, 결과를 PR "검증 방법과 결과" 칸에 적는다. 9항목)

| # | 항목 | 방법 |
|---|---|---|
| 1 | 근거 | 사실 문장의 출처를 확인한다. `tools/doc-check`가 일반화 단어(많다·대부분·일반적·보통·흔히·업계·자주)를 경고하면 하나씩 근거를 달거나 뺀다 |
| 2 | 숫자 | 모든 숫자를 계산식으로 다시 계산한다. 시간·횟수·금액은 최악의 경우도 계산한다 |
| 3 | 모듈 호출 | 새로 생긴 "A → B" 호출을 모두 뽑아 ADR-001 표와 대조한다. 표에 없는 호출, 순환(A → B와 B → A가 같이 있음)이 0이어야 한다. 값이 다른 모듈에 있으면 "누가 그 값을 가져다 주나"까지 본다 |
| 4 | 다른 ADR과 충돌 | 승인·제안 ADR 전부에서 같은 테이블·상태·값·쓰기 방식·경로를 검색해 비교한다. 특히 승인된 ADR의 문장과 다르면 보충(A7)이나 대체가 필요하다 |
| 5 | 계약·규칙과 충돌 | 작업진행.md B(계약)·A(규칙)·E1(돌발 상황)·`.claude/rules/`와 비교한다. 바꾸는 결정이면 "기획·계약 변경"으로 표시하고, 바뀌는 절(B1 모듈 책임, B3 그림, A5 규칙 포함)을 빠짐없이 "문서 반영 체크"에 적는다 |
| 9 | 상태·조치 표의 빈칸 | 상태 표와 조치 표가 모든 조합을 덮는지 본다. 특히 "이미 끝난 상태에 같은 신호가 다시 오는 경우"(정상 승인 뒤의 웹훅 등)가 예외 칸으로 떨어지지 않는지, 새 상태로 **들어오는** 전이가 정의됐는지 본다 |
| 6 | 강제 범위 | "강제" 칸의 도구가 실제로 무엇을 잡고 무엇을 못 잡는지 나눠 적었다. 검사 코드는 **역검사**를 한다: 위반 예시를 넣거나 지키려는 설정을 끄면 검사가 실제로 실패하는지 돌려 본다(빌드 도구가 결과를 재사용해 시험을 건너뛰지 않는지도 본다). 검사의 판정 기준은 그 검사가 지키려는 실제 설정(보안 필터 경로 등)과 글자 그대로 같아야 한다 |
| 7 | 미룬 일 등록 | "나중에·미확인·R?에서 정한다·확인한다" 문구마다 작업진행.md E4-2(또는 해당 작업 행)에 언제 다시 볼지 등록했다. 닫힌 이슈에만 적지 않는다 |
| 8 | 지도·목록 | 새 파일·폴더를 CLAUDE.md §1, 작업진행.md A2, ADR 목록(`docs/adr/README.md`)에 넣었다. `tools/doc-check` 오류 0 |

## 3층: 단위 끝, 최종 보고 전

- [ ] **여정 따라가기**: 관련 여정(작업진행.md C3)과 E-ID 실패 경로를 단계 표로 걸었다(단계, 호출하는 모듈 → 호출받는 모듈, 바뀌는 상태, 잠금). 아래 현실 조건을 하나씩 대입했다.
- [ ] **독립 검토**(단위당 한 번): 작성 과정을 모르는 AI 에이전트에게 "오류·누락·모순을 찾아라"로 검토시켰다. 반영 뒤 확인은 직접 검색으로 하고, 두 번째 에이전트는 사용자가 요청할 때만 쓴다. 지적마다 확인해 반영하거나, 반영하지 않은 이유를 보고에 적었다.
- [ ] `tools/doc-check` 오류 0. 남은 경고는 이유를 보고에 적었다.
- [ ] 보고서 검증 칸에 한 것과 안 한 것을 나눠 적었다.

**현실 조건 목록** (여정 따라가기에 대입한다)

| 조건 | 예시 질문 |
|---|---|
| 탭·창 여러 개 | 두 탭이 동시에 토큰을 갱신하면? 두 탭에서 결제하면? |

| 서버 재시작·중간 실패 | 커밋 직후, 외부 호출 직후에 죽으면 무엇이 남나? |
| 순서 뒤바뀜 | 웹훅·폴링 결과가 늦게·거꾸로 오면? |
| 동시 경합 | 고객과 운영자, 배치와 요청이 같은 행을 동시에 건드리면? |
| 배포 경로 | Nginx·도메인·경로 규칙에서 이 주소가 백엔드에 닿나? 보안 필터 체인의 어느 쪽인가? |
| 모바일·브라우저 | 결제창을 닫으면 서버가 아나? 인앱 브라우저에서는? |
| 악용 | 이 기능을 일부러 반복·위조하면 남을 막거나 비용을 쓰게 할 수 있나? 공개 경로에 요청 한도가 있나? 요청자가 보낸 헤더(IP 등)를 그대로 믿나? |
| 부분 실패 | 여러 건(SKU 여러 개 등) 중 일부만 성공하면 무엇이 남나? 되돌리는 방법이 정해졌나? |
| 개발 환경 | DB를 초기화하면 외부에 남은 값(멱등키 등)과 겹치나? localhost에서 동작하나? |
